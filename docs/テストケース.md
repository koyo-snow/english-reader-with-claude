# テストケース

`英語読書アシスタント（Electron）仕様書.md` の各項目を、どのテストで確かめているかの対応表。個々のテストケースはテストコードの題名にそのまま書いてある（例: `TREE-04 フォルダが先、次にファイル。それぞれ名前の昇順…`）。一覧は次のコマンドで出せる。

```bash
npx vitest list             # 単体テスト
npx playwright test --list  # E2E
```

## テストの種類

| 種類 | 場所 | 実行 | 何を確かめるか |
| --- | --- | --- | --- |
| 単体（Vitest） | `tests/unit/` | `npm test`（CI でも実行） | メインプロセスのロジック（Vault、設定の保存、Claude 呼び出し、読み上げ、メニュー）と、レンダラーの純粋な処理（Markdown、検索、入力単位、保存内容）。`electron`・Claude Agent SDK・`say` は差し替える。 |
| E2E（Playwright + Electron） | `tests/e2e/` | `npm run test:e2e`（ローカルのみ。CI では動かさない） | ビルドしたアプリを起動し、画面を操作して確かめる。設定の保存先と Vault はテストごとの一時フォルダ（`--user-data-dir`）で、本物の設定や Vault には触らない。 |
| 手動 | この文書の「手動で確かめる項目」 | リリース前 | 実際の Claude、実際の音声、実際のキー入力など、自動では確かめられないもの。 |

E2E では、外に出ていく処理をメインプロセス側で差し替えている（`tests/e2e/support/app.ts`）。

- Claude の呼び出し：レンダラーが送ったリクエストを記録し、テストから応答イベント（セッション開始・差分・完了・エラー）を流す。`ClaudeRunner` 自体は単体テストで確かめる。
- 読み上げ：`say` を起動せず、渡された文章を記録する。
- 外部ブラウザ・フォルダ選択ダイアログ・クリップボード・確認ダイアログ：OS には出さず、記録または固定値を返す。
- メニューのショートカット：キー入力ではなく、メニュー項目を直接実行する（キー入力そのものは手動で確かめる）。

## 仕様との差分として記録しているテスト

実装が仕様（または当然期待される動き）を満たしていないと分かった項目は、テストを消さずに「失敗するはず」の印（Vitest は `it.fails`、Playwright は `test.fail()`）を付けてある。テスト全体は通るが、実装を直すと「失敗するはずが成功した」と報告されるので、そのとき印を外す。

| ID | 内容 | 原因 |
| --- | --- | --- |
| MD-39（E2E） | Mermaid のフローチャートで、ノードのラベル（文字）が表示されず箱だけになる | ラベルは `<foreignObject>` 内の HTML として出力されるが、`sanitizeSvg`（DOMPurify）がその中身を取り除く |
| JSON-32（E2E） | 読書位置・ハイライト・ツリーの開閉が、アプリを終了するまで `state.json` に書き出されない | ファイルを開いている間、スクロール位置の保存が約 0.4 秒ごとに繰り返し発生し続け（`App.tsx` の `onScroll` が `appState.scroll` に依存している）、0.5 秒待ってから書く処理が毎回先送りになる。通常の終了時には保存される |
| LAY-07（E2E） | 左右のドロワーを最大幅にすると、既定のウィンドウ幅（1280）で本文ビューが 120px しか残らない | 左の最大 520 + 右の最大 640 が、ウィンドウ幅に関係なく固定 |
| CL-34（単体） | 完了の通知（done）が 2 回届く | 結果を受け取った後、「結果が来ずに終わった場合」の処理も通る。画面側は 2 回目を無視するので実害はない |
| MD-14（単体） | 未対応の言語名（` ```dataview ` など）のコードブロックを初めて描画するとき、`renderMarkdown` が 1 回例外を投げる | Shiki の `loadLanguage` が同期的に例外を投げる。画面では React が描画をやり直すので表示は崩れない（E2E の MD-38 は通る） |

## 手動で確かめる項目

自動テストでは差し替えている、または確かめられない部分。`npm run build` で作った `.app` を Finder から起動して確かめる。

| # | 確かめること | 仕様書の章 |
| --- | --- | --- |
| M-01 | Finder から起動した `.app` で、`claude` が自動検出されて実行できる（シェルの PATH を引き継がない状態） | Claude 連携／実装上の注意：PATH |
| M-02 | 実際の Claude で、回答がストリーミングで少しずつ表示される | 下ドロワー：表示 |
| M-03 | 追加質問が、前の回答を踏まえた内容で返ってくる | 下ドロワー：追加質問 |
| M-04 | プロンプトごとのモデル指定（Opus / Sonnet / Haiku）と、応答言語（日本語 / English）が実際の回答に効く | Claude 連携：モデル、応答言語 |
| M-05 | 生成中の「停止」で、実際に生成が止まる | 下ドロワー：停止 |
| M-06 | `claude` で未ログインの状態、利用上限に達した状態で、それぞれのエラー表示になる | Claude 連携：エラー表示 |
| M-07 | 実行後、Vault の中に `.claude/` などが作られていない | Claude 連携：作業ディレクトリ |
| M-08 | Cmd+L / Cmd+R / Cmd+D / Cmd+F / Cmd+, / Cmd+Enter を実際にキーボードで押して動く。Cmd+R でページが再読み込みされない。ほかのアプリにフォーカスがあるときは効かない | ショートカット |
| M-09 | 「読み上げ」で実際に音が出る。英語の文は英語の音声、日本語の文は日本語の音声で読まれる | 読み上げ、言語ごとの音声 |
| M-10 | 読み上げ中にスライダーを動かすと、いま読んでいる塊の頭から新しい速度で読み直される。「停止」で音が止まる | 読み上げ速度 |
| M-11 | 外部リンクとタイムスタンプのクリックで、既定のブラウザが開く（YouTube は該当時刻から再生される） | レンダリング：リンク、字幕のタイムスタンプ |
| M-12 | 設定タブの「選択…」で macOS のフォルダ選択ダイアログが開き、選んだ Vault が開く | 左ドロワー：Vault の指定 |
| M-13 | テーマ「システム連動」で、macOS の外観（ライト／ダーク）を切り替えると追従する | 読書体験：表示設定 |
| M-14 | ウィンドウを別のディスプレイに置いて終了し、そのディスプレイを外して起動しても、画面内に表示される | ドロワーの動作：ウィンドウ |
| M-15 | Obsidian で Vault のファイルを編集・追加・削除すると、ツリーと本文に反映される | 左ドロワー：ファイル監視 |
| M-16 | 実際の字幕ファイル（数 MB）で、スクロールと検索が引っかからない | 実装上の注意：大きなファイル |
| M-17 | 本文の何もないところで右クリックして、メニューの「段落」の対象が意図した段落になっている（macOS は右クリックで単語を選択することがある） | 右クリックメニュー |
